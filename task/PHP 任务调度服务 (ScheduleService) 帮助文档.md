# PHP 任务调度服务 (ScheduleService) 帮助文档

## 1. 模块简介

`ScheduleService` 是一个基于 PHP 的轻量级任务调度器模块。它的主要作用是扫描并处理系统中配置的循环任务（基于 Cron 表达式），将符合执行条件的任务生成实例并加入执行队列。该调度器设计为无状态或单次执行模式，推荐配合外部进程管理工具（如 Supervisor）进行循环调用，从而保证任务调度的高可用性与进程隔离性。

## 2. 核心类 ScheduleService 方法说明

### 2.1 公开方法

- **`runOnce(): bool`**
  执行一次完整的调度扫描流程。该方法会尝试获取文件锁，初始化未设置下次执行时间的任务，扫描并处理到期任务。执行完毕后自动释放锁。设计为单次执行，推荐由外部进程管理工具（如 Supervisor）循环调用。

- **`run(): void`**
  调度器的主循环方法（兼容模式）。该方法会在内部启动一个 `while(true)` 死循环，每 3 秒调用一次 `runOnce()`。此模式仅建议在开发调试阶段使用，生产环境不推荐。

### 2.2 内部核心方法

- **`initializeNextRun(): void`**
  初始化所有启用的循环任务的 `tsnextrun` 字段。针对数据库中 `tsnextrun` 为 0 的任务，解析其 Cron 表达式并计算出首次执行时间。

- **`scanAndSchedule(): void`**
  扫描并调度到期的循环任务。查询所有 `tsnextrun` 小于等于当前时间戳的启用任务，并逐个交由 `processSchedule` 进行处理。

- **`processSchedule(array $schedule, int $now): void`**
  处理单个循环任务配置。在数据库事务中完成以下操作：计算下次执行时间、创建任务实例入队、更新调度配置记录，以保证数据的一致性。

- **`calculateNextRun(array $schedule, int $now): int`**
  计算任务的下次执行时间。基于 `CronExpression` 库，根据上次执行时间（或当前时间）推算下一次触发时间。若推算出的时间小于等于当前时间（说明系统有延迟），则立即标记为当前时间执行。

- **`createTaskInstance(array $schedule, int $now): int`**
  创建任务实例。将调度配置映射为具体的任务数据（包含任务类名、载荷、最大重试次数、超时时间等），验证后插入到 `task` 表中，返回生成的任务 ID。

- **`updateSchedule(int $tsid, int $now, int $nextRun): void`**
  更新调度配置。在任务实例成功创建后，更新对应调度记录的 `tslastrun`（上次运行时间）、`tsnextrun`（下次运行时间）以及 `tstimes`（累计执行次数）。

- **`acquireLock(): bool`**
  获取分布式文件锁。使用 `flock` 的非阻塞排他锁（`LOCK_EX | LOCK_NB`）机制，防止多个调度器实例同时执行。

- **`releaseLock(): void`**
  释放分布式文件锁。解锁并关闭文件句柄，通常在 `runOnce` 的 `finally` 块中调用，确保锁一定会被释放。

## 3. 使用方式说明

调度器通过 CLI 脚本进行调用，支持通过命令行参数切换运行模式：

```bash
# 单次执行模式（推荐）
php scheduler.php once

# 持续运行模式（仅用于调试）
php scheduler.php loop
```

### 模式区别与推荐

- **单次执行模式 (`once`)**：脚本执行完一次扫描后即退出。**强烈推荐在生产环境中配合 Supervisor 等进程守护工具使用**。这种方式可以有效避免 PHP 长时间运行导致的内存泄漏问题，且进程崩溃后 Supervisor 会自动重启，容错率极高。
- **持续运行模式 (`loop`)**：脚本在后台常驻内存，每 3 秒自动扫描一次。仅适用于本地快速调试，不建议在生产环境使用。

## 4. 注意事项

1. **文件锁机制**：调度器强依赖文件系统锁来防止并发执行。请确保运行 PHP 脚本的用户对锁文件所在目录（默认为系统配置的 `tmpDir`）具有读写权限。在分布式多节点部署时，需注意本地文件锁无法跨节点生效，需自行改造为 Redis 等分布式锁。
2. **事务处理**：任务的实例化与调度配置的更新被包裹在同一个数据库事务中。这确保了“生成任务”与“更新下次执行时间”的原子性，避免了任务重复生成或漏调度的问题。
3. **Cron 表达式解析**：底层依赖 `CronExpression` 库，请确保项目中已正确安装相关依赖。若 Cron 表达式配置错误，可能会导致任务初始化失败，请留意控制台输出的 `[ERROR]` 日志。
4. **超时与重试**：创建任务实例时，默认设置了 300 秒（5分钟）的执行超时时间。具体的重试机制与超时处理需由下游的任务 Worker 消费端配合实现。
